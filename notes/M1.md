# M1 — Páginas e arquivo de dados

## Para que serve

O M1 é a base de tudo: é ele que **guarda e lê os dados em um arquivo**.

Um banco de dados não escreve os dados soltos no arquivo. Ele divide o arquivo em blocos de tamanho igual, chamados **páginas**. Assim, para achar uma informação, o banco calcula em que página ela está e vai direto lá.

## Os números importantes

| Nome no código | Valor | O que é |
|----------------|-------|---------|
| `PAGE_SIZE` | 4096 | Tamanho de cada página, em bytes |
| `HEADER_SIZE` | 16 | Bytes reservados no começo de cada página |
| `RECORD_SIZE` | 8 | Tamanho de um registro |
| `SLOTS_POR_PAGINA` | 510 | Quantos registros cabem em uma página |

## Como um registro vira bytes

Um registro tem dois números: `id` e `matrícula`. Cada um ocupa 4 bytes, então o registro tem 8 bytes. Usamos a biblioteca `struct` do Python para converter:

```python
import struct
struct.pack("<II", 42, 2026100)    # números -> 8 bytes
struct.unpack("<II", dados)        # 8 bytes -> números
```

O `"<II"` quer dizer:
- `<` → little-endian (o byte menos importante vem primeiro)
- `I` → número inteiro sem sinal de 4 bytes (duas vezes, um para cada campo)

## Onde fica cada registro

```text
byte no arquivo = (página × 4096) + 16 + (slot × 8)
```

Slot 0 da página 2 → `8192 + 16 + 0` = **8208**.

## O que cada função faz (`source/storage.py`)

| Função / método | O que faz |
|-----------------|-----------|
| `DiskStorage(caminho)` | Abre o arquivo (ou cria, se não existir) |
| `le(n)` | Lê a página `n` e devolve 4096 bytes |
| `escreve(n, conteudo)` | Grava 4096 bytes na página `n` |
| `aloca()` | Cria uma página nova (só zeros) no fim do arquivo |
| `sync()` | Garante que tudo foi gravado no disco de verdade |
| `fecha()` | Faz o `sync()` e fecha o arquivo |
| `calcula_deslocamento(p, s)` | Calcula o byte onde começa o registro |
| `serializa_registro(id, mat)` | Transforma o registro em 8 bytes |
| `desserializa_registro(dados)` | Transforma 8 bytes de volta em `(id, mat)` |
| `grava_registro_slot(...)` | Grava um registro em (página, slot) |
| `le_registro_slot(...)` | Lê o registro de (página, slot) |

`Pager` é só outro nome para `DiskStorage`.

## Proteções (o programa avisa com erro quando algo está errado)

- Página com tamanho diferente de 4096 bytes → `ValueError`.
- Ler uma página que não existe → `IOError`.
- Número de página negativo → `ValueError`.
- Slot fora do intervalo de 0 a 509 → `ValueError`. (Sem isso, um slot negativo gravaria em cima do cabeçalho.)
- Abrir um arquivo cujo tamanho não é múltiplo de 4096 → `ValueError` (arquivo corrompido).

## Detalhe importante: flush vs fsync

- `flush()` manda os dados do Python para o sistema operacional.
- `fsync()` manda do sistema operacional para o disco de verdade.

Sem o `fsync`, uma queda de energia poderia fazer o dado sumir, mesmo o programa achando que gravou. Por isso o `sync()` usa os dois.

## Por que `bytearray` e não `bytes`?

Quando lemos uma página, devolvemos um `bytearray`, que **pode ser alterado**. Já o `bytes` normal é fixo e não deixaria a gente mudar um pedaço da página. Como queremos mexer em partes da página (por exemplo, só um slot), usamos `bytearray`.

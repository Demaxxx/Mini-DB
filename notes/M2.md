# M2 — Cache de páginas (Buffer Pool)

## Para que serve

Ler do disco é **muito mais lento** do que ler da memória RAM. Se o programa pede a mesma página várias vezes, não faz sentido ir ao disco toda vez.

O **Buffer Pool** (ou cache) guarda algumas páginas na memória. Ele fica entre o programa e o disco:

```text
Programa  <-->  BufferPool (memória)  <-->  DiskStorage (disco)
```

## Hit e miss

- **Hit (acerto)**: a página já estava no cache. Foi rápido.
- **Miss (falha)**: a página não estava no cache e teve que ser lida do disco.

`hit_ratio` mostra a taxa de acerto: `hits ÷ (hits + misses)`. Quanto mais perto de 1.0 (100%), melhor.

## O que o cache guarda (`source/cache.py`)

```python
self.paginas = {}   # número da página -> conteúdo
self.sujas = set()  # páginas alteradas que ainda não foram para o disco
self.ordem = []     # ordem de uso (a mais antiga fica na frente)
```

## LRU: quem sai quando o cache enche?

O cache tem um limite (padrão: 8 páginas). Quando está cheio e chega uma página nova, precisamos tirar alguém. A regra **LRU** (*Least Recently Used*) escolhe a página que está **há mais tempo sem ser usada**.

Exemplo com capacidade 2:

| Passo | Ação | `ordem` (antiga → recente) |
|-------|------|----------------------------|
| 1 | pede página 0 | `[0]` |
| 2 | pede página 1 | `[0, 1]` |
| 3 | pede página 0 de novo | `[1, 0]` (a 0 ficou mais recente) |
| 4 | pede página 2 (cache cheio!) | sai a **1** → `[0, 2]` |

## Página suja (dirty) e write-back

Quando alteramos uma página na memória, o disco ainda tem a versão antiga. Chamamos essa página de **suja**.

Gravar no disco a cada pequena alteração seria lento. Então o cache espera, e só grava quando:

1. a página suja **sai** do cache (para dar lugar a outra), ou
2. chamamos `flush()` / `close()`.

Isso se chama **write-back** (escrita adiada). Se a página está limpa, ela sai sem gravar nada.

## O que cada método faz

| Método | O que faz |
|--------|-----------|
| `get_page(n)` | Devolve a página `n` (do cache ou do disco) |
| `mark_dirty(n)` | Avisa que a página `n` foi alterada |
| `write_page(n, dados)` | Troca a página inteira e já marca como suja |
| `flush_page(n)` | Grava só a página `n` no disco (se estiver suja) |
| `flush()` | Grava todas as páginas sujas e faz o `sync` |
| `evict(n)` | Tira a página `n` do cache (grava antes, se estiver suja) |
| `clear()` | Faz o flush e esvazia o cache |
| `close()` | Faz o flush e fecha o arquivo |
| `contains(n)` | Diz se a página `n` está no cache |

Também existem `hits`, `misses`, `hit_ratio` e `dirty_pages` para acompanhar o que está acontecendo.

`PageCache` é só outro nome para `BufferPool`.

## Regra de ouro

`get_page()` devolve a **própria página que está no cache**, não uma cópia. Se você alterar os bytes dela, **tem que chamar `mark_dirty(n)`**. Se esquecer, a alteração fica só na memória e **se perde**.

Dica: se você já tem a página inteira pronta, use `write_page(n, dados)`, que marca como suja sozinho.

## Usando `with`

```python
with BufferPool(disco, capacidade=4) as cache:
    pagina = cache.get_page(0)
    pagina[0:3] = b"abc"
    cache.mark_dirty(0)
# Ao sair do "with", o cache faz flush e fecha o arquivo sozinho,
# mesmo que aconteça um erro no meio.
```
